The minimal layout language — four keys

The LLM declares the frame (flow, rails, where the ICs go, which nets exit). Everything else is inferred from connectivity by a small fixed rule set. No per-part placement, no orientation flags, no geometry.

The entire language
flow: lr # global signal direction (default lr) — optional rails: { +5V: top, GND: bottom } # nets drawn as spanning lines + band place: { U1: [1,0], MCU: [2,-1] } # coarse cells — usually just the ICs; # ANY refdes may be pinned to override ports: { OUT: right, 5V_BUS: left } # nets that exit as edge flags + side

That's it. place takes a coarse unitless cell, never mm. Most parts aren't listed at all — they're placed by inference.

The fixed inference rules (the only "magic", and it's small & predictable)

  1. A pin on a rail-net → vertical stub up/down to that rail.
  2. A 2-pin part with one pin on the top rail and one on the bottom rail → vertical, between the rails (decoupling / divider leg).
  3. A 2-pin part tapping a single IC pin → sits on that pin's side, oriented along the pin.
  4. A run of 2-pin parts on a shared private net → series chain laid along the route between its endpoints.
  5. Unplaced ICs without cells → ordered along flow by their net adjacency.

Five rules total. If a circuit needs something they don't give, the LLM just pins that part in place — the same primitive, no new grammar.

All four cases in this language

divider-filter
rails: { VCC: top, GND: bottom } ports: { OUT: right } # R7,R8,C3 all inferred: # R7 VCC->mid, R8/C3 mid->GND
555-blinker
rails: { +9V: top, GND: bottom } place: { U1: [1,0] } # caps flank left, R's flank right # by which U1 pin they tap
mcp1703-power-entry
flow: lr rails: { +5V: top, +3V3: top, GND: bottom } place: { U1: [1,0] } ports: { 5V_BUS: left } # F1 left of U1 (chain to 5V_BUS port) # C1,C2 under +5V; C3,C4 under +3V3 # D1,R2 right of +3V3 -> GND
uart-level-translator
rails: { VCC3V3: top, VCCD: top, GNDD: bottom } place: { J1: [0,0], U2: [1,0], MCU: [2,-1] } ports: { TXD1: ?, RXD1: ? } # pullups -> VCC rails, decouplers # under rails, series R's in-line

The intelligence lives in the deterministic engine (the 5 rules + a good router), not in a sprawling grammar the LLM must memorize. The LLM only needs to understand four keys. Does this hit the "minimal & elegant" bar?
