# Plan 4: Agent Loop + TUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`). TDD where testable; the agent-core tasks are testable against real Bedrock, the TUI task is verified by manual run. Per-task gate: `cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --check`.

**Goal:** Make the founding prompt work as an interactive copilot: a user types "Design me a bluepill STM32H7 with USB and I2C", the agent (real LLM) drives tools to synthesize an ERC-clean `.kicad_sch`, shows a diff, and on approval writes it next to a running KiCAD — then follow-up prompts modify it without destroying user edits.

**Architecture (spec §10–11):** A new `agent` crate owns the LLM client (delegated to `rig-core`/`rig-bedrock`, BYOK config), a tool registry over the existing crates, and the agent loop with a human apply-gate. The `autopcb` binary gains a `ratatui` TUI cockpit. The six tools (spec §10) map onto what's already built:

| Tool | Backed by |
|---|---|
| `get_design()` | `sch_engine::lift::lift` (current .kicad_sch → canonical YAML) |
| `search_symbols(q)` | `kicad_bridge::search::SymbolIndex` |
| `get_symbol_info(lib_id)` | `kicad_bridge::geometry`/`symlib` (pin table) |
| `validate_design(yaml)` | `circuit_lang::compile` (no write) |
| `apply_design(yaml)` | `circuit_lang::compile` → `sch_engine::emit_design_reconciled` → diff → gate → write + snapshot → ERC |
| `run_erc()` | `kicad_bridge::cli::KicadCli::erc` |

Ground truth for the agent's system prompt is in memory `real-validation-findings` (plain refdes, pin-number fallback for stacked names, real lib_ids). The validated system prompt + self-repair loop are already proven in `/tmp/auto-pcb-spike` (the Bedrock spike): grounded one-shot compiled clean; ungrounded self-repaired in one round. The `.env` holds `AWS_BEARER_TOKEN_BEDROCK` + `AWS_REGION`.

**Tech stack:** Rust 2024. New deps: `rig-core` + `rig-bedrock` (verify exact crates/versions at plan time — they move fast; if `rig-bedrock` is immature, fall back to a thin direct Bedrock Converse client over `reqwest`, mirroring the proven `/tmp/auto-pcb-spike/call_bedrock.py` request shape: `POST https://bedrock-runtime.{region}.amazonaws.com/model/{id}/converse`, `Authorization: Bearer {token}`). `ratatui` + `crossterm` + `tokio`. `notify` (file watch, Task 6).

**Testing policy:** Agent-core tests that hit Bedrock are gated on `AWS_BEARER_TOKEN_BEDROCK` being set (SKIP-graceful) AND marked `#[ignore]` by default (they cost money + need network) with a documented `cargo test -- --ignored` to run them; the bluepill end-to-end agent test (Task 4) is the key one to run manually. Tool-layer tests are deterministic (mock LLM / direct tool calls) and run in the normal gate.

### Task 2: Tool registry over the existing crates

**Files:** Create `crates/agent/src/tools.rs`; test `crates/agent/tests/tools.rs`.

Each tool is `{ def: ToolDef, run: Fn(serde_json::Value, &mut ToolCtx) -> ToolResult }`. `ToolCtx` holds the `KicadEnv`, the `RealSymbolProvider`, the project's `.kicad_sch` path, and a `SnapshotStore`. Tools are pure-ish wrappers — the real logic already exists.

## Definition of done

- **MVP criterion #1 as a copilot:** the founding prompt, typed into the agent (TUI or headless), drives real Bedrock + tools to produce an ERC-clean `.kicad_sch` with a human apply-gate (Tasks 3–5).
- **MVP criterion #2:** a follow-up prompt ("add an SPI flash") modifies the design without disturbing user-repositioned symbols (reconciliation, already built — exercised via the agent in Task 4/5).
- **MVP criterion #3:** the user can edit in eeschema between turns and the agent sees it (Task 6).
- All gates green; Bedrock/KiCAD tests run manually and pass.
- Deferred (recorded): power-symbol styling, pretty wire routing, Pillar 2 (part sourcing) and Pillar 3 (PCB layout) — their own specs.
